# Question 12: Who comprises the typical buying committee (IT ops, CIO, procurement, end users)?

## Answer

The typical ITSM buying committee includes **10-11 stakeholders** in mid-market organizations and up to **25-33 influencers** in enterprises. Two-thirds of committee members are **outside IT**. The CFO holds final approval power in 79% of purchases, but IT leadership (CIO, IT Director) drives evaluation and recommendation.

---

## Executive Summary

| Metric | Value |
|--------|-------|
| **Average committee size (overall)** | 25 influencers |
| **Enterprise committee size** | 33 influencers (17 IT + 16 LOB) |
| **SMB committee size** | 15 influencers (7 IT + 8 LOB) |
| **Purchases with single decision-maker** | 48% |
| **Purchases requiring committee** | 52% |
| **End users with input in decision** | 72% |
| **Non-IT stakeholders influencing purchase** | 32% |
| **CFO holds final approval** | 79% |

## Stakeholder Deep Dive

### 1. CIO / Chief Information Officer

#### Profile

| Attribute | Description |
|-----------|-------------|
| **Role** | Executive sponsor, strategic alignment |
| **Authority** | Final decision-maker (often shared with CFO) |
| **Focus** | Business alignment, risk, long-term strategy |
| **Reports to** | CEO, Board |

#### 2024-2025 CIO Priorities

| Priority | Rank | Implication for ITSM |
|----------|------|---------------------|
| **Cybersecurity & Risk** | #1 (4th consecutive year) | Security certifications, compliance matter |
| **AI / Generative AI** | #2 | AI capabilities expected, not optional |
| **Operational Efficiency** | #3 | Productivity gains, automation |
| **Vendor Consolidation** | Rising | Fewer tools preferred; platform plays win |
| **ROI / Value Creation** | Constant | Must demonstrate measurable outcomes |
| **Data Governance** | Rising | Data quality foundation for AI |

#### What CIOs Care About

| Concern | Questions They Ask |
|---------|-------------------|
| **Strategic alignment** | "Does this support our digital transformation goals?" |
| **Risk mitigation** | "What are the security and compliance implications?" |
| **Vendor viability** | "Will this vendor be around in 5 years?" |
| **Total cost** | "What's the true TCO, not just license cost?" |
| **Integration** | "How does this fit our existing tech stack?" |
| **AI readiness** | "What AI capabilities are included?" |

#### How to Engage CIOs

| Approach | Rationale |
|----------|-----------|
| Lead with business outcomes | They care about impact, not features |
| Show strategic alignment | Connect ITSM to their priorities |
| Address risk proactively | Security, compliance, vendor stability |
| Provide executive references | Peer validation from similar organizations |
| Quantify ROI | CFO will ask; CIO needs the data |

### 2. CFO / Finance Leadership

#### Profile

| Attribute | Description |
|-----------|-------------|
| **Role** | Budget authority, financial approval |
| **Authority** | Final approval power (79% of purchases) |
| **Focus** | ROI, TCO, budget alignment, risk |
| **Reports to** | CEO, Board |

#### What CFOs Care About

| Concern | Questions They Ask |
|---------|-------------------|
| **ROI** | "What's the payback period? What's the NPV?" |
| **TCO** | "What's the full cost including implementation, training, maintenance?" |
| **Budget fit** | "Is this in budget? Which line item?" |
| **Risk** | "What happens if this fails? What's the exit cost?" |
| **Vendor terms** | "What are the payment terms? Can we negotiate?" |
| **Compliance** | "Are there any financial/regulatory implications?" |

#### TCO Components CFOs Evaluate

| Category | Components |
|----------|------------|
| **Initial costs** | License, implementation, data migration, training |
| **Ongoing costs** | Subscription, maintenance (15-25% annually), support |
| **Hidden costs** | Customization, integration, internal resources |
| **Exit costs** | Data extraction, migration to new vendor |

#### How to Engage CFOs

| Approach | Rationale |
|----------|-----------|
| Provide detailed TCO analysis | They'll calculate it themselves if you don't |
| Show ROI with conservative assumptions | Credibility matters more than optimistic projections |
| Offer flexible payment terms | OPEX vs. CAPEX, annual vs. monthly |
| Compare to alternatives | "vs. current state" and "vs. competitors" |
| Highlight cost avoidance | Reduced headcount needs, avoided incidents |

### 3. IT Director / VP of IT

#### Profile

| Attribute | Description |
|-----------|-------------|
| **Role** | Operational and strategic IT leadership |
| **Authority** | Strong recommendation power; may have approval for smaller deals |
| **Focus** | IT strategy alignment, operational efficiency, team capability |
| **Reports to** | CIO |

#### What IT Directors Care About

| Concern | Questions They Ask |
|---------|-------------------|
| **Operational fit** | "Will this actually work in our environment?" |
| **Team adoption** | "Can my team learn and use this effectively?" |
| **Integration** | "How does this connect to our monitoring, CMDB, etc.?" |
| **Support quality** | "What's the vendor support like?" |
| **Roadmap** | "Where is this product going in 2-3 years?" |
| **Migration** | "How painful is migration from our current tool?" |

#### How to Engage IT Directors

| Approach | Rationale |
|----------|-----------|
| Provide technical depth | They understand technology; don't oversimplify |
| Show integration architecture | API documentation, pre-built connectors |
| Offer POC/trial | They want hands-on validation |
| Share customer references | Similar industry/size organizations |
| Present roadmap | They plan long-term |

#### Profile

| Attribute | Description |
|-----------|-------------|
| **Role** | Day-to-day IT operations leadership |
| **Authority** | Heavy influencer; shapes requirements |
| **Focus** | Operational efficiency, team productivity, SLA achievement |
| **Reports to** | IT Director or CIO |

#### What IT Ops Managers Care About

| Concern | Questions They Ask |
|---------|-------------------|
| **Efficiency** | "Will this reduce our workload or add to it?" |
| **Reporting** | "Can I get the metrics I need to manage my team?" |
| **Automation** | "What can be automated out of the box?" |
| **Customization** | "Can we adapt workflows to how we actually work?" |
| **Performance** | "Is it fast? Will it slow us down?" |
| **Training** | "How long until my team is productive?" |

#### How to Engage IT Ops Managers

| Approach | Rationale |
|----------|-----------|
| Focus on productivity gains | Time savings, reduced manual work |
| Show reporting/dashboards | They live in metrics |
| Demonstrate automation | Workflow automation, auto-routing |
| Provide training resources | Accelerate team adoption |
| Offer configuration flexibility | Every org has unique processes |

### 5. Service Desk Manager

#### Profile

| Attribute | Description |
|-----------|-------------|
| **Role** | Manages service desk team and operations |
| **Authority** | Heavy influencer; often leads evaluation |
| **Focus** | Agent productivity, customer satisfaction, SLA compliance |
| **Reports to** | IT Ops Manager or IT Director |

#### What Service Desk Managers Care About

| Concern | Questions They Ask |
|---------|-------------------|
| **Agent experience** | "Will my agents actually like using this?" |
| **Ease of use** | "How intuitive is the interface?" |
| **Ticket management** | "How easy is it to create, update, resolve tickets?" |
| **Knowledge base** | "Can agents quickly find answers?" |
| **Self-service** | "Will this reduce ticket volume through self-service?" |
| **Reporting** | "Can I track agent performance and SLAs?" |

#### How to Engage Service Desk Managers

| Approach | Rationale |
|----------|-----------|
| Demo the agent experience | Show day-in-the-life workflows |
| Highlight UX design | Modern, intuitive interface matters |
| Show self-service portal | Ticket deflection is a key goal |
| Demonstrate knowledge management | Agent enablement is critical |
| Provide benchmark data | Resolution time, satisfaction improvements |

### 6. Procurement

#### Profile

| Attribute | Description |
|-----------|-------------|
| **Role** | Process gatekeeper, contract negotiation |
| **Authority** | Gatekeeper (can slow/stop deals); not decision-maker |
| **Focus** | Process compliance, cost optimization, risk mitigation |
| **Reports to** | CFO or COO |

#### What Procurement Cares About

| Concern | Questions They Ask |
|---------|-------------------|
| **Process compliance** | "Did we follow our procurement policy?" |
| **Competitive bidding** | "Did we get multiple quotes?" |
| **Contract terms** | "Are the terms favorable? Any red flags?" |
| **Pricing** | "Is this competitive? Can we negotiate better?" |
| **Vendor risk** | "Is this vendor financially stable? Compliant?" |
| **Renewal terms** | "What are the auto-renewal and price increase terms?" |

#### How to Engage Procurement

| Approach | Rationale |
|----------|-----------|
| Provide transparent pricing | Reduces back-and-forth |
| Offer standard contract terms | Speeds legal review |
| Share security certifications | SOC 2, ISO 27001, etc. |
| Be responsive to RFP process | They manage timelines |
| Provide competitive comparison | Justifies selection |

| Attribute | Description |
|-----------|-------------|
| **Role** | Security and compliance validation |
| **Authority** | Veto power on security grounds |

## Committee Dynamics by Company Size

### SMB (< 200 employees)

| Factor | Typical Pattern |
|--------|-----------------|
| **Committee size** | 1-5 people |
| **Decision-maker** | Often single (IT Manager or Owner) |
| **Key influencers** | IT Manager, Service Desk Lead |
| **Process** | Informal; fast decisions |
| **Priorities** | Price, ease of use, quick deployment |

### Mid-Market (200-2,000 employees)

| Factor | Typical Pattern |
|--------|-----------------|
| **Committee size** | 5-15 people |
| **Decision-maker** | IT Director + CFO approval |
| **Key influencers** | IT Ops, Service Desk, Procurement |
| **Process** | Semi-formal; some RFP elements |
| **Priorities** | Balance of features, price, support |

### Enterprise (2,000+ employees)

| Factor | Typical Pattern |
|--------|-----------------|
| **Committee size** | 15-33 people |
| **Decision-maker** | CIO + CFO + Steering Committee |
| **Key influencers** | Multiple IT teams, Security, Procurement, Legal |
| **Process** | Formal RFP; extended evaluation |
| **Priorities** | Enterprise scale, security, compliance, integration |

## Navigating the Buying Committee

### Common Challenges

| Challenge | Impact |
|-----------|--------|
| **Conflicting priorities** | IT wants features; Finance wants low cost |
| **Lack of consensus** | 56% of purchases result in buyer remorse |
| **Late stakeholder involvement** | Objections emerge late in process |
| **Shadow IT influence** | Departments adopt tools without IT input |
| **Turnover** | Key contacts leave during long sales cycles |

### Success Strategies

| Strategy | Application |
|----------|-------------|
| **Map all stakeholders early** | Identify decision-makers, influencers, blockers |
| **Understand individual priorities** | Each stakeholder has different concerns |
| **Find and enable a champion** | Internal advocate who sells on your behalf |
| **Provide role-specific content** | Technical docs for architects; ROI for finance |
| **Address objections proactively** | Don't wait for them to surface |
| **Build consensus iteratively** | Regular check-ins prevent late surprises |

### Content Mapping by Stakeholder

| Stakeholder | Content Types |
|-------------|---------------|
| **CIO** | Executive summary, strategic alignment, peer references |
| **CFO** | ROI calculator, TCO analysis, pricing comparison |
| **IT Director** | Technical architecture, roadmap, integration docs |
| **IT Ops Manager** | Demo, POC, workflow documentation |
| **Service Desk Manager** | Agent UX walkthrough, benchmark data |
| **Procurement** | Pricing sheet, security certs, standard contract |
| **Security** | SOC 2 report, penetration test summary, data flow diagram |
| **End Users** | Self-service demo, mobile app, Slack/Teams integration |
